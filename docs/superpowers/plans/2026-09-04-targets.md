# Targets implementation plan

> **For agentic workers:** Implement task-by-task. Checkboxes track progress. Spec is the source of truth.

**Goal:** Ship the demand side of the transfer market — a `Targets` board where managers post targets (a named player or a positional profile, public or private), matched at write time against listings, auctions and drops, and joined to the Listings board at every surface where the two meet.

**Source of truth:** `docs/superpowers/specs/2026-09-04-targets-design.md`.

**Tech stack:** Next.js App Router, CSS Modules, Supabase (new table + RLS + realtime publication), existing `createNotification` / push / prefs stack, existing `useLiveTransfers` realtime patch pattern.

## Global constraints

- `npm run build` and `npm test` must pass before declaring done.
- Migration applied via Supabase MCP `apply_migration` against project **Gaffa** (`hnkavimrsbytsesdzwvj`), not left as a paste instruction. Verify realtime publication with `execute_sql`, not `list_migrations`.
- RLS policies use `(select auth.uid())`, never a bare `auth.uid()` — migration 145 exists to fix exactly that lint.
- **A private target must never leak.** Realtime honours RLS, and the board subscribes. The select policy is the only guard; test it directly against the DB, not just through the UI.
- CSS Modules only; reuse `--color-*` tokens; check both themes (Cream Editorial and Premium Dark).
- Copy never says "FAAB", "wishlist", "trade block", or "scouting" for any part of this. Money as `€{n}m`. Clubs take a plural verb.
- Internal and external naming match: `player_targets`, `targetStance`, `TargetCard`. No FAAB-style split.
- No new cron, no new `vercel.json` entry, no client polling. Targets expire on a read filter; matching runs at write time on a targeted query.
- Matching and notification code is best-effort and wrapped — it must never fail the listing insert or the drop it hangs off.
- **UI goes through a design prototype before it gets built.** See Task 6.

- [x] Exclude the owner/seller's own team, and re-check the targeting team does not already roster the player.

## Task 7: UI

- [ ] `TargetCard.tsx` — deliberately quieter than `ListingCard`: no countdown, no bid affordance. When a live listing matches, render it inline with the listing's own Bid button. The target never grows actions of its own.
- [ ] Card actions, per the spec's flows — the pre-fill is the feature:
  - Profile target → `ProposeBuilder`, counterparty set, give-side picker **filtered to my players at that position**, their cash seeded to their stated budget.
  - Named target on **my** player → two actions, not one: "Make an offer" (`ProposeBuilder`, that player on my give side, their budget as the cash asked) **and** "List him" (`ListingEditor` pre-filled with him). Offering only the first systematically undersells to whoever asked first.
  - Named target on a third party's player → no action; informational.
  - Secondary on every card: "Message them" → chat DM.
- [ ] `ChatClient.tsx`: accept `?dm=<userId>` and open that thread on mount. It currently has no `useSearchParams` at all, so this is a real (small) addition, not a link you can just point at.
- [ ] `TargetEditor.tsx` — kind toggle, visibility toggle reading "Visible to the league" / "Only you", three stance checkboxes, budget, 140-char note.
- [ ] `targets/page.tsx` + `TargetsClient.tsx` following the Listings page structure. Facets `all / named / profiles / cash / trade / loan / mine`; sorts newest, budget, position. `primePlayers` to seed the card cache.
- [ ] `TransfersSubNav`: `Targets` after `Listings`. **Check six tabs at 375px** — if it doesn't fit, shorten `Free Agency` to `Free Agents`, don't drop a tab or add a scroller.
- [ ] `useLiveTransfers`: subscribe to `player_targets`, patch over the server model, same `router.refresh()` re-seed.
- [ ] `MarketClient`: demand section beside "On the Listings Board" (around line 314).
- [ ] `ListingCard`: demand line — "Chelsea want him", or "3 clubs are looking for a CB" when only profiles match.
- [ ] `ListingEditor`: matching targets at the top.
- [ ] Entry points: `PlayerDetailsModal`, `PlayerHub`, `FreeAgentsClient`, and player rows on the Listings board. **Not** the roster Inspector — that shows players you own, where the right action is "List for transfer", already there.

## Task 8: Match hooks

- [x] `POST /listings` route: inside the existing best-effort notification block (route.ts:319–357), call `matchTargets` with the listing's floor and send the target-available notice to each match. Keep the existing league-wide `listedNotice` — they serve different readers.
- [x] Two-sided check: if the listed player already has active targets, send the stronger two-sided notice to both sides instead of the plain pair.
- [x] `seedHighValueAuctions.ts`: same call alongside the arrival notices it already sends.
- [x] `executeDrop.ts`: same call after the auction is seeded.
- [x] Auto-fill **named targets only** — implemented as a trigger (`154_fill_targets_on_acquisition.sql`), not application code: acquisitions are written from at least five places and nearly all are PL/pgSQL, so a TS hook would have to be remembered by every future one.
- [x] **Do not auto-fill profiles.** Signing one LB does not end a search for an LB. Profiles end on withdrawal or expiry. Getting this wrong silently deletes people's targets.
- [x] A target survives its player being traded to another club in the league — matching re-points at the new owner. No special handling needed; just don't add code that kills it.
- [x] Every hook wrapped in try/catch with a `console.error` prefix matching the house pattern.

## Out of scope (do not build)

- Auto-generated targets from squad holes.
- Anonymous visibility (a third mode, addable later without reshaping anything here).
- Targets on retained rights, academy players, or draft picks.
- Any transactable behaviour on a target — no bidding, no accepting, no auto-generated offers.
- Any change to listings mechanics: auction timing, the €50m threshold, `seedHighValueAuctions` eligibility, or `resolve_single_player_auction_rpc`.
- Commissioner moderation of note text.
- Dropping the deprecated `roster_entries.on_trade_block` column. Unrelated cleanup that would widen this change for no benefit.
